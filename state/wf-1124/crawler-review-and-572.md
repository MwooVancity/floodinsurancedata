## Task A: tools/crawl_like_google.py (101 lines), real bugs only

1. L58, L69, L86 (VERIFIED code; GUESS effect): `--limit N` crawls only `urls[:N]`, but `site` and the orphan test use the full sitemap and only crawled pages supply inbound links. With `--limit 50` on a 5,000-URL sitemap, almost every crawled page is linked from an uncrawled page, so it is reported as "orphan" (ERROR, exit 1). False positives on any partial run.
2. L78: a page's own link to itself counts as an inbound link (no `l != u` test). A page that has a self-link (breadcrumb, nav item, language link) is never reported as an orphan even if nothing else links to it. False negatives.
3. L57-59, L99: if the sitemap fetch fails (get returns status 0, body ""), `allu` is empty, no pages are crawled, no errors are added, and the script prints "crawled 0 pages; ERRORS 0" and exits 0. The status `st` of the sitemap is printed but never checked. A dead or blocked sitemap looks like a clean pass. Same for a robots.txt failure (L55-56).
4. L58: the sitemap is read with one `<loc>` regex. A sitemap index file would return child sitemap URLs as if they were pages (each then fails the canonical check as an ERROR, and no real page is crawled). Also not handled: `.gz` sitemaps, `&amp;` in a loc, whitespace or CDATA around the URL (no strip/unescape).
5. L78-79: internal links are normalised with `rstrip("/")+"/"` before matching the sitemap, so a link to `/x` that 301-redirects to `/x/` counts as a good inbound link and is never fetched, so the redirect is missed. Links beginning `http://` or `https://www.` fail `startswith(BASE)` and are never checked at all, so internal links that redirect through protocol/host are missed. A link whose last path segment contains a dot or a query string with a dot is skipped by the `"." not in ...` test.
6. L41-42, L43, L72, L93: noindex detection is partial. Meta name is compared case-sensitively and only to "robots", so `<meta name="googlebot" content="noindex">` and `name="Robots"` are missed; `rel="canonical"` is matched only when rel is exactly that (a `rel="canonical nofollow"` or uppercase is missed, then reported as a canonical error). The `X-Robots-Tag` response header is never read (get() drops headers), so a header noindex is invisible. L93 checks the substring "noindex" in the first 6000 characters (not bytes) of the body: any visible text, script or comment mentioning the word in that window hides an "indexable page missing from sitemap" ERROR, and a real noindex meta after 6000 characters (large inline CSS in head) is missed.
7. L21-30, L63: only network exceptions are retried. An HTTP 429 or 5xx raises HTTPError and returns at once, with no retry and no Retry-After wait. Under rate limiting the page becomes an ERROR and is dropped from `pages` (L63 `continue`), so every page that was linked only from it then shows as an orphan: one 429 produces a cascade of false orphan errors. A status 0 page (L29-30) is reported as "HTTP 0" with no mention of the fetch failure.
8. L71 and L78: canonical test compares the raw href string to the URL minus trailing slash, so a relative canonical (`/flood-insurance/x/`), an `http://` canonical, or a case difference is reported as "not itself" (false ERROR) even when it resolves to the same URL (no urljoin). Separately L78 rebuilds `{x.rstrip("/")+"/" for x in site}` inside the per-link loop: with about 5,000 pages and about 100 links each this is on the order of billions of operations (GUESS, not timed); build the set once.

Not reported (judged minor): `--limit` as last arg raises IndexError; `Disallow` count regex; title entity handling.
